# Инъекция шаблона через ключи map, SSRF во внутреннюю сеть и IDOR

**Кубок CTF России 2025, квалификация · web · `trustmebroker` · решено**

> **TL;DR** — сервис санитизирует значения, которые получает, и пересылает всё тело запроса
> целиком, вместе с именами полей, во внутренний сервис генерации PDF. Тот подставляет
> их в шаблон глобальной заменой подстрок. Имена полей не фильтруются и не ограничены по длине,
> поэтому в документ, который рендерит headless Chrome во внутренней сети, можно записать
> произвольный HTML. Цепочка замен снимает ограничение в 17 байт, и Chrome превращается
> в SSRF-клиент к админке, которая наружу не опубликована вообще.

**Стек:** Go 1.25 / Fiber v2, headless Chrome (Puppeteer) для PDF, SQLite
**Классы:** template injection, SSRF, IDOR, ошибка проектирования валидации

---

## Что было дано

`docker-compose` поднимает три сервиса, наружу смотрит один:

| сервис | что это | порт |
|---|---|---|
| `web` | Go 1.25 / Fiber v2 + SQLite | 8080, публичный |
| `admin` | админка | 9090, только внутренняя сеть |
| `pdf` | генератор PDF | 3000, только внутренняя сеть |

Исходники выданы только для `web`. `admin` и `pdf` — чёрные ящики.

Отсюда сразу понятно, что флаг не может лежать в `web`: интересное начинается там, куда `web`
способен дотянуться во внутренней сети.

## Разведка

Маршрутов ровно шесть: `/register`, `/register/step1..3`, `/finish`, `/agreement`.
Всё остальное отдаёт 404, статика не обходится через `..`.

С `admin` сервис `web` не разговаривает вообще. Он обращается только к `pdf`, причём отправляет
туда **всё тело запроса целиком**:

```go
http.Post(pdfBaseURL+"/render", "application/json", <весь payload>)
```

Готовый PDF выдаёт себя метаданными:

```
/Creator (… HeadlessChrome/154.0.0.0 …)  /Producer (Skia/PDF m154)
```

Значит, HTML, на который влияет пользователь, рендерит настоящий Chrome внутри сети.
Если в этот HTML удастся что-то записать, Chrome станет средством доступа к `admin:9090`.

## Где вход

Тело запроса парсится в `map[string]string`, то есть сервис принимает **произвольные ключи**,
и вся карта — включая незнакомые ему поля — уходит в `pdf`.

Санитизация выглядит так:

```go
func sanitize(a string) string {
    a = strings.ReplaceAll(a, "<", "")   // и > " ' \
    cut := 17
    if len(a) < 17 { cut = len(a) }
    return a[:cut]
}
```

и применяется вот как:

```go
for k := range in { in[k] = sanitize(in[k]) }   // только значения
```

| канал | фильтруется | ограничение длины |
|---|---|---|
| значения | `<>"'\` вырезаются | 17 байт |
| **имена ключей** | **нет** | **нет** |
| кука `agreement_id` | параметризованный SQL | — |

Значения для инъекции бесполезны: `<` через них не пронести. Ключи свободны полностью.
В этом и весь баг.

## Что делает PDF-сервис

Значения подставляются в документ сырыми, без экранирования — `a&amp;b` рендерится как `a&b`.
То есть единственное, что мешает инъекции через значения, — вырезанный `<`.

Решающее наблюдение пришло не оттуда. Я начал фаззить **имена** ключей и увидел странное:
односимвольные ключи — `a`, `}`, `;`, `"` — стабильно разносили вёрстку документа, а любой ключ
из двух и более символов не делал ничего.

Это подпись наивной глобальной замены подстроки: односимвольный ключ встречается в тексте
шаблона повсюду, двухсимвольный — нигде. Проверяется в один запрос:

```json
{"Фамилия": "ZZZZZ"}
```

и подпись `Фамилия:` в PDF превращается в `ZZZZZ:`. Подтверждено: сервис выполняет
`html.replaceAll(key, value)` для каждой пары из payload.

Раз можно переписывать произвольные куски документа — можно и прочитать его целиком. Перетегировать
`<body>` в `<plaintext>`:

```json
{"body": "plaintext"}
```

и браузер отдаёт остаток документа текстом, включая `<div class="meta">Номер заявки: …</div>`.

## Снятие ограничения в 17 байт

`len("http://admin:9090") == 17` — ровно предел санитайзера. Совпадение не случайное: ограничение
подобрано так, чтобы внутренний адрес влезал в значение, а разметку вокруг него давал ключ.

Но 17 байт мало для осмысленного URL с путём. Снимается это композицией.

`json.Marshal` в Go сортирует ключи при сериализации, а V8 сохраняет порядок вставки — значит,
замены выполняются в детерминированном порядке, и более поздняя замена может развернуть токен,
который вставила предыдущая. Из кусков по 17 байт собирается строка любой длины:

```
"div class=" -> "iframe zza src="
"meta"       -> "zzc"
"zza"        -> "width=760 zzb"
"zzb"        -> "height=3000"
"zzc"        -> "zzd:9090/zze"
"zzd"        -> "http://admin"
"zze"        -> <путь, при необходимости тоже по кускам>
```

`<div class="meta">` превращается в `<iframe width=760 height=3000 src="http://admin:9090/…">`,
и Chrome рендерит внутреннюю админку прямо в PDF, который я же и скачиваю.

## От SSRF к чужим данным

Через этот примитив нашёлся `GET /agreements` — постраничный список заявок (`?page=N`),
319 записей из той же SQLite. Список отдаёт `agreement_id` каждой заявки, но не паспортные поля.

Дальше — IDOR. `GET /agreement` авторизует исключительно по куке `agreement_id`: любой
утёкший идентификатор даёт полный PDF чужого заявителя.

Флаг лежит в заявке с seed-идентификатором 6, разложенный по четырём паспортным колонкам,
**по 17 символов в каждой** — отсюда и взялась цифра в санитайзере:

| поле | фрагмент |
|---|---|
| Серия | `ctfcup{61d402f23f` |
| Номер | `8f16637cff1c08f30` |
| Кем выдан | `3bebc9a9eaf19abf0` |
| Дата выдачи | `56f988fcab69ef43}` |

```
$ python3 exploit.py
[+] leaked 10 agreement_id(s) from the internal admin panel
[+] hit on agreement_id=a916728b5c3ceec5d94e2c9011a419f8
FLAG: ctfcup{61d402f23f8f16637cff1c08f303bebc9a9eaf19abf056f988fcab69ef43}
```

## Защита

**Санитизация должна покрывать объект целиком, а не половину.** `for k := range in { in[k] =
sanitize(in[k]) }` обрабатывает значения и молча пропускает ключи. Правильно — проверять
структуру: принимать только известный набор полей, остальное отбрасывать до любой обработки.
Тогда неизвестный ключ перестаёт быть каналом ввода.

**`replaceAll` не шаблонизатор.** Замена подстрок по всему документу не знает границ HTML-узлов
и ничего не экранирует. Нужен движок шаблонов с контекстным экранированием и фиксированным
списком переменных.

**Внутренний сервис не значит доверенный.** `admin:9090` не опубликован наружу, и это считалось
защитой. Но рендерер — полноценный браузер во внутренней сети: как только в его HTML можно
писать, он работает прокси для атакующего. Браузер-рендерер держат в изолированном сетевом
неймспейсе, без доступа к внутренним сервисам, с запретом внешних подресурсов.

**Авторизация не держится на идентификаторе из куки.** `GET /agreement` проверяет только
`agreement_id`, поэтому утечка идентификатора равна доступу к чужим паспортным данным.
Привязка должна быть к сессии, а не к объекту.

**Ограничение длины не заменяет валидацию содержимого.** Лимит в 17 байт выглядел как
hardening, а на деле задал размер блока, из которого собирается произвольная строка.

## Что стоит унести

Считать нужно каналы ввода, а не параметры: тело распарсено в `map[string]string` — значит,
ключи это тоже вход, причём необработанный.

Разница между «односимвольный ключ ломает вёрстку, двухсимвольный не делает ничего» выглядит как
шум, а является подписью конкретной реализации. Аномалию, которую легко списать на мусор, стоит
дожимать до объяснения.

Детерминированный порядок замен превращает набор независимых подстановок в цепочку, и ограничение
«не больше 17 байт» снимается композицией.
