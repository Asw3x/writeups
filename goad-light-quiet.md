# GOAD Light тихо: та же цепочка с оглядкой на детект

**Лаборатория · Active Directory · [GOAD Light](https://github.com/Orange-Cyberdefense/GOAD) · про шум, а не про флаг**

> **TL;DR** — второй проход по той же лаборатории, но с вопросом «что из этого увидит защитник».
> Половина действий из [основного разбора](./goad-light-full-chain.md) выполняется тише без
> потери результата: LDAP вместо SMB для перечисления, точечная проверка портов вместо
> сканирования, Kerberos-билеты в AES без принудительного даунгрейда до RC4, BloodHound только
> с контроллера домена. И одно место, где я всё равно засветился — не техникой, а темпом.

**Классы:** OPSEC, выбор протокола под задачу, темп запросов, пассивная разведка

---

## Нулевой шаг: ничего не отправлять

Прежде чем стучать во что-либо, стоит просто послушать сеть:

```bash
sudo tcpdump -i <интерфейс> -n udp port 137 or arp
```

NBT-NS и ARP идут широковещательно, их генерируют сами хосты. Отсюда получаешь список живых
машин, не отправив ни одного пакета в их сторону. Для детекта этого не существует: нет запроса —
нет события.

## Чем можно стучать, а чем нельзя

Не все протоколы одинаково заметны. Практическое разделение, к которому я пришёл:

| | насколько заметно |
|---|---|
| `ldap` | можно всегда. LDAP-запросы — штатный фон домена, их делают все рабочие станции постоянно |
| `smb` | точечно. Каждое подключение — событие входа, аномалия видна по количеству, а не по факту |
| `winrm`, `rdp` | перебор исключён. С валидной учёткой — пожалуйста, но подбор по ним палится сразу |

Отсюда правило: **перечислять пользователей и группы лучше через LDAP, а не через SMB.**
Результат тот же, следов меньше.

Отдельно про флаги перебора. `-u users.txt -p passwords.txt` или `-h hashes.txt` в netexec —
это серия попыток аутентификации за секунды. В логах это видно мгновенно и выглядит ровно тем,
чем является. Если нужен перебор, он делается медленно, с одной попыткой на учётку за окно
блокировки, и начинается не раньше, чем исчерпаны бесплатные источники.

## Порты: проверять, а не сканировать

Полный `nmap -p-` по хосту домена — это гарантированное попадание в отчёт. Если известно,
какие порты интересны, они проверяются поштучно:

```bash
nc -z -w 2 <ip> 88     # Kerberos
nc -z -w 2 <ip> 389    # LDAP
nc -z -w 2 <ip> 445    # SMB
```

Для контроллера домена набор предсказуем, и три точечных подключения вместо 65535 меняют картину
в логах полностью.

## Бесплатные источники до любого перебора

Если на хосте разрешена анонимная сессия, с нулевой учётной записью доступны:

```bash
netexec smb <ip> -u '' -p '' --users      # список пользователей
netexec smb <ip> -u '' -p '' --pass-pol   # политика паролей
netexec smb <ip> -u '' -p '' --shares     # шары
```

Это три запроса, которые дают список учётных записей и — что важнее — **политику блокировки**.
Без неё любой последующий перебор это стрельба вслепую: не зная порога, легко заблокировать
реальных пользователей и превратить тихую работу в инцидент.

## Kerberos: не понижать шифрование и не торопиться

AS-REP Roasting и Kerberoasting сами по себе тихие — это штатные запросы к KDC:

```bash
GetNPUsers.py <домен>/<пользователь>:<пароль> -dc-ip <ip> -request
GetUserSPNs.py <домен>/<пользователь>:<пароль> -dc-ip <ip> -request
```

Заметными их делают две вещи, обе — на стороне атакующего.

**Принудительный даунгрейд до RC4.** Многие инструменты по умолчанию просят билет с
шифрованием RC4, потому что его быстрее ломать. Но в домене, где всё работает на AES, запрос
именно RC4-билета — это аномалия, по которой пишут правила детекта. Запрашивать в AES-256
дороже при переборе хэша, зато не выделяется на общем фоне.

**Темп.** Пачка TGS-запросов ко всем SPN подряд за секунду выглядит не так, как работа
пользователя. Задержки между запросами стоят минут и снимают основной признак.

## BloodHound: собирать только с контроллера

```bash
bloodhound-python -c DCOnly -u <пользователь> -p <пароль> -d <домен> -dc <fqdn> -ns <ip> --zip
```

Режим `DCOnly` берёт данные из LDAP контроллера домена и **не обходит все хосты сети**. Сбор
по умолчанию (`-c All`) честно опрашивает каждую машину — сессии, локальные группы, реестр, —
и это десятки подключений к десяткам хостов за короткое время. На графе разница небольшая,
в логах — принципиальная.

## Где я всё равно засветился

На `tcpdump`, который так и работал фоном, в какой-то момент появился широковещательный пакет
от хоста `.22` — машина объявила о себе, и я увидел собственный след.

Причина оказалась не в технике, а в темпе. Сами по себе одиночные `nc -z` — тихий метод. Но я
сделал **двенадцать подключений к одному хосту за пару секунд**. Для системы это не двенадцать
нормальных обращений, а очередь, и она отличается от фонового трафика именно плотностью.

Главное отсюда: заметность определяется интервалом, а не инструментом. Тот же `nc`, разложенный по минуте, не отличается от обычного клиента. Он же
за две секунды — скан.

Поэтому `tcpdump`, запущенный до начала работы, полезен не только для разведки. Он показывает твою же работу со стороны сети — дешёвая обратная связь по OPSEC,
которую больше взять негде.

## Что попутно нашлось в LDAP

Перечисление через LDAP, помимо списка пользователей, отдаёт атрибуты, которые на SMB не видны.
По контроллеру домена:

```
SPN:  CIFS/<dc>.<домен>
      HTTP/<хост>.<домен>
Trusted For Constrained Delegation: TRUE
```

Ограниченное делегирование на контроллере — это отдельная ветка атаки, и нашлась она бесплатно,
тем же запросом, которым собирался список учёток. Ещё один аргумент в пользу LDAP: он не только
тише, он информативнее.

## Что увидел бы защитник

| Действие | Событие | Чем ловится |
|---|---|---|
| Анонимная сессия SMB | вход с пустыми учётными данными | 4624 с Logon Type 3 и пустым пользователем |
| Перечисление через LDAP | штатный запрос | почти ничем — нужен baseline по объёму запросов на учётку |
| Перебор `-u/-p/-h` | серия 4625 за секунды | тривиально, это основное правило в любом SIEM |
| Запрос TGS с RC4 в AES-домене | 4769 с типом шифрования 0x17 | одно из самых надёжных правил на Kerberoasting |
| `bloodhound -c All` | десятки подключений к десяткам хостов | аномалия по числу уникальных назначений за окно |
| Пачка подключений к одному хосту | всплеск плотности | не сигнатурой, а порогом |

Закономерность: всё, что ловится надёжно, ловится **по объёму и темпу**, а не по содержанию
отдельного запроса. Защита, построенная на сигнатурах конкретных инструментов, обходится
переименованием бинаря; защита, построенная на базовой линии поведения, — нет.

## Выводы

- Тишина — это выбор протокола под задачу и выдержка по времени, а не отдельный набор команд.
  Тот же результат достижим и шумно, и тихо.
- Бесплатные источники (анонимная сессия, LDAP, политика паролей) отрабатываются полностью
  до первого перебора. Чаще всего после них перебор уже не нужен.
- Настройки по умолчанию в инструментах оптимизированы под скорость, а не под незаметность:
  RC4 вместо AES, `-c All` вместо `DCOnly`, полный скан вместо точечной проверки.
- Собственный сниффер, запущенный до начала работы, — самый дешёвый способ увидеть себя
  глазами защитника.
